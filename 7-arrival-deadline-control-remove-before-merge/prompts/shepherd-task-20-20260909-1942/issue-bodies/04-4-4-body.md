Research on the prepared MyFaces/Open Liberty baseline established that `<f:metadata>` must be directly under the root `<html>`, before `<h:head>` and `<h:body>`; nesting it in the body causes view-component failures. Implement the established interaction from production conventions, not from spike code.

## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDateDialog.java`
- `src/main/webapp/admin/dialogs/changeArrivalDeadlineDate.xhtml`

Implement a serializable launcher using:

```java
@ManagedBean(name = "changeArrivalDeadlineDateDialog")
@SessionScoped
```

Provide `showDialog(String trackingId)`, `handleReturn(SelectEvent event)`, and `cancel()`. `showDialog` must pass `trackingId` as `Map<String, List<String>>`, use the exact options above, and open the exact dialog path. `cancel()` closes with an empty string and must not invoke the facade. Preserve the destination-dialog return lifecycle.

The XHTML title must be `Change Deadline`. Directly beneath root `<html>` and before `<h:head>`, add:

```xhtml
<f:metadata>
    <f:viewParam name="trackingId"
                 value="#{changeArrivalDeadlineDate.trackingId}"/>
    <f:viewAction action="#{changeArrivalDeadlineDate.load}"/>
</f:metadata>
```

Display visible, associated labels and values for Origin (`cargo.originName`), Destination (`cargo.finalDestinationName`), and Deadline. Bind a required `p:datePicker` to `changeArrivalDeadlineDate.arrivalDeadlineDate` and render validation feedback. Add Cancel calling `changeArrivalDeadlineDateDialog.cancel()` and Update calling `changeArrivalDeadlineDate.changeArrivalDeadline()`. Refresh/reload the calling Administration view after successful return following the established destination-dialog behavior.
